# ADR-0029: HTTP 도구 노드 보안 — 도메인 허용 목록, 해석 뒤 IP 차단, 비밀 참조

## Status
Accepted (2026-10-24, 사용자 결정)

## Context
HTTP 도구 노드는 테넌트가 그린 흐름에서 서버가 외부 URL을 부르는 기능이다. 공개 위젯·`/try`의 방문자 입력이
URL·헤더·본문에 섞일 수 있어 SSRF(사설망·메타데이터 엔드포인트 접근), DNS 리바인딩, 리다이렉트 우회, 느린·큰 응답으로
워커를 묶는 공격, 비밀 키 유출이 모두 열린다. 운영 박스는 컨테이너 55개가 있는 공용 Oracle 박스라 내부망 노출이 특히 위험하다.

## Decision
- **도메인 허용 목록**: 테넌트가 등록한 **HTTPS 도메인**만 부른다(정확한 호스트 일치, 와일드카드는 명시적으로 등록한 하위 도메인 형태만).
  `http://`, IP 리터럴 호스트, 사용자 정보(`user@host`), 기본 외 포트는 거부한다.
- **해석 뒤 IP 차단**: 호스트를 DNS로 해석한 **모든** 주소를 검사해 사설(RFC 1918, ULA `fc00::/7`), 루프백, 링크로컬
  (`169.254.0.0/16`, `fe80::/10`), 메타데이터(`169.254.169.254`, `fd00:ec2::254` 등), 미지정·브로드캐스트·멀티캐스트·CGNAT
  (`100.64.0.0/10`), IPv4 매핑 IPv6를 거부한다. **검사한 그 IP로 연결**한다(해석과 연결 사이 리바인딩 차단, SNI·Host는 원래 호스트).
- **리다이렉트마다 다시 검사**: 자동 따라가기를 끄고, 각 `Location`을 허용 목록·스킴·해석 IP 검사에 다시 통과시킨다. 최대 횟수를 둔다.
- **자원 상한**: 전체 시간 **5초**(연결·읽기 포함), 응답 본문 **256KB**까지(스트리밍으로 읽다가 넘으면 끊고 실패).
- **비밀**: 테넌트 비밀(API 키 등)은 암호화해 저장한다(기존 Fernet 방식). 흐름 JSON에는 `{{secret.이름}}` **참조만** 둔다.
  치환은 요청을 만들 때 서버에서만 한다. 판단 기록·로그·오류 메시지에서는 비밀 값을 가린다(원문과 일치하는 부분 문자열 포함).
  - **가림의 출처와 범위(#115·#118)**: 테넌트가 읽는 출력(판단 기록·시험 대화 SSE trace·MCP `test_turn`)은 **그 테넌트가 DB에
    저장한 비밀 전체**(복호화)와 그 테넌트로 등록된 파생값(Basic base64 등, `register_revealed`)으로 가린다. 프로세스가 본 값만
    가리면 비밀을 저장한 api 워커와 대화를 돌리는 worker-chat이 달라 원문이 그대로 나간다(#118 운영 확인). 테넌트별 캐시는
    30초(`STORED_TTL_SECONDS`) 믿고, 지나면 비밀 표의 `(개수, max(updated_at))`만 읽어 바뀌었을 때만 다시 복호화한다. 같은
    프로세스의 저장·삭제는 즉시 무효화, 다른 프로세스의 변경은 30초 안에 따라잡는다(치환이 캐시가 모르는 값을 만나면 즉시).
    비밀이 없는 테넌트는 빈 집합을 캐시한다. Redis 버전 키는 두지 않았다 — 표 집계 한 번이 충분히 싸고 무효화 경로가 하나 준다.
    로그는 운영자만 보므로 프로세스가 본 모든 값(저장·치환·캐시 적재 때 오름)으로 가리고, LogRecord 팩토리에서 DB를 부르지 않는다.
  - **위협 모델**: 가림은 테넌트 범위라 **다른 테넌트 비밀의 오라클은 없다** — B가 임의 문자열을 넣어도 B 출력엔 A 비밀로 인한
    `[비밀]`이 생기지 않는다. 반면 **같은 테넌트 Member는 시험 대화에 후보 문자열을 넣고 어디가 `[비밀]`로 바뀌는지 보아 자기
    테넌트 비밀을 6자 조각 단위로 맞춰 볼 수 있다.** 값 열람·쓰기는 Admin만(`SECRETS_MANAGE`)이지만, 이 오라클은 Member도 쓸 수
    있다. Member는 그 테넌트가 들인 신뢰된 내부자로 보고 받아들인다 — 가림의 목적은 기록·화면·로그로 **우연히** 새는 것을 막는
    것이고, 같은 테넌트 안의 의도적 추측까지 막으려면 가림을 끄는 수밖에 없는데 그러면 원문이 그대로 남는다.
- **`/try`에서는** 실제 외부 호출 대신 예제용 가짜 API만 부른다.
- **보안 시험을 먼저 쓴다**: 위 규칙마다 실패하는 시험(사설 IP로 해석되는 도메인, 리다이렉트로 메타데이터, 시간 초과, 크기 초과,
  기록에 비밀 노출)을 먼저 만들고 구현한다. 외부 DNS·서버는 시험 안의 결정적 대역(로컬 리졸버 주입, 로컬 HTTPS 서버)으로 둔다.

## Considered Options
- **차단 목록만(허용 목록 없음)**: 기각. 차단 범위를 하나 놓치면 바로 SSRF다.
- **송신 프록시(Smokescreen 등) 컨테이너**: 보류. 박스 메모리가 빠듯하다. 애플리케이션 계층 검사로 시작하고, 필요해지면 앞에 둔다.
- **흐름 JSON에 비밀을 암호문으로 박기**: 기각. 버전이 바뀌지 않아 키 회전 때 모든 버전을 다시 써야 한다.

## Consequences
- HTTP 클라이언트는 「해석 → 검사 → 그 IP로 연결」을 하는 전용 계층으로 감싼다(일반 `httpx` 호출 금지). sandcorp-auth의 CIMD 가져오기(#20)와 같은 방식이다.
- 테넌트 설정에 「허용 도메인」과 「비밀」 화면이 생긴다(비밀은 쓰기 전용, 조회 시 이름만).

## 보충 (#108): 테넌트가 넣은 URL — 허용 목록 없는 「공용 호스트만」 정책

HTTP 도구 노드 말고도 서버가 테넌트가 넣은 URL을 부르는 곳이 있었다 — 웹 문서 가져오기(`rag/web.py`), 에스컬레이션 웹훅(`escalation/webhook.py`), custom LLM·임베딩·OCR Provider의 `base_url`(LLM SDK·임베딩·모델 목록). 셀프 가입이 열린 운영에서 이들은 IP 검사 없이 `httpx`/`requests`로 불렀다(웹 문서는 응답이 지식으로 저장돼 검색·챗으로 읽히는 SSRF).

- **정책**: `PublicHosts(schemes)` — 도메인 허용 목록만 없고 나머지는 위 결정 그대로다: IP 리터럴 거부, 해석한 **모든** IP 검사, 검사한 IP로 연결, 리다이렉트마다 다시 검사, 전체 시간·본문 상한. 기본 포트만(http 80·https 443).
- **웹 문서**: http·https. 공개 웹 문서는 아직 http만 주는 곳이 있고, 응답을 사람이 다시 보는 지식이라 기밀 전송 요구가 없다. 상한은 20초·**5MB**·리다이렉트 5회 — 보통 문서 페이지 HTML이 수백 KB~1MB대라 256KB로는 잘리고, http→https→www 사슬이 흔하다. 시간 초과·연결·DNS 실패만 인제스션 태스크가 다시 시도한다.
- **웹훅**: https만. 본문에 상담 대화가 실린다. 10초·응답 64KB·리다이렉트 3회. 저장 때 형식(https·IP 리터럴·포트)을 보고, 해석·IP 검사는 보낼 때마다 한다. 실패는 로그(사유 코드·호스트·해석 IP)+예외 — 재시도·DLQ는 소비자 런타임 그대로.
- **custom Provider**: 저장(·모델 목록 조회) 때 `check_provider_url` — https, userinfo 없음, 해석한 IP 모두 공용(포트는 자유 — 자체 호스팅 엔드포인트가 흔히 8443 등을 쓴다). **부를 때도** 검사한다: LLM SDK(`ChatOpenAI`)·임베딩·모델 목록이 쓰는 httpx 클라이언트에 연결 순간마다 해석·IP 검사를 하는 httpcore 네트워크 백엔드를 단다(`guarded_http_client`). TLS의 SNI·인증서 검증은 원래 호스트로 한다. 저장 뒤 DNS가 사설로 바뀌어도(리바인딩) 연결하지 않는다. 체험 플랫폼 키의 `api.openai.com`도 같은 길이며 공용이라 통과한다. Anthropic 네이티브는 고정 주소(`api.anthropic.com`)뿐이다.
- **dev·test**: 내부 호스트(fake-llm·ollama·로컬 시험 서버)를 써야 하므로 `OUTBOUND_PRIVATE_ALLOWED=True`(dev.py)일 때만 사설 주소·http·임의 포트를 허용한다. 기본(base.py)과 운영(prod.py)은 False로 고정 — env로 바꿀 수 없다. `PLATFORM_DEFAULT_PROVIDERS_ENABLED`와 따로 둔 까닭: 하나는 비용(플랫폼 키 폴백), 하나는 보안(사설 송신)이라 한쪽을 켜려다 다른 쪽이 열리면 안 된다.
- **사용자 문구**: `user_message(code)`가 사유를 한국어로 만든다(예: 「이 주소는 가져올 수 없습니다: 내부망·사설 주소입니다」). 해석한 IP는 사용자 문구에 넣지 않고 로그에만 남긴다.
- 네트워크 모듈 import 묶음(`test_only_the_safe_layer_opens_new_outbound_connections`)에서 테넌트 URL을 부르던 모듈을 뺐다. 남은 예외는 플랫폼 고정 주소(인증 서버 token·JWKS)와 예외 타입만 쓰는 `rag/tasks.py`뿐이다.

## 보충 (#34): HTTP 도구 노드 실행 — 호스트 고정, 틀 치환, 리다이렉트, 실패 갈래

- **호스트는 틀의 고정 부분**: `url`의 `https://` 뒤 첫 `/`·`?`·`#`까지(호스트·포트·사용자 정보)에 `{{…}}`가 있으면 저장 때 `invalid_config`.
  상태 값(`{{state.user_message|label|confidence}}`·`{{state.fields.이름}}`)은 경로·쿼리에만, 실행 때 **한 조각으로** 퍼센트 인코딩한다
  (`quote(safe="")` + `.` → `%2E`: `/`·`?`·`#`·`&`·`%`·`..`로 경로를 거슬러 오르거나 쿼리를 끼워 넣지 못한다). 치환 뒤 호스트가 틀의 호스트와
  다르면 실패(닫힌 쪽 이중 확인). 허용 목록만으로는 같은 테넌트의 다른 허용 호스트로 방문자가 요청을 돌릴 수 있어, 고정으로 정했다.
- **헤더에는 방문자 값을 못 쓴다**(고정 글과 `{{secret.…}}`만, 줄바꿈·`Host`·`Content-Length`·`Transfer-Encoding`·`Connection`·`Upgrade`·`TE` 금지).
  본문의 참조 값은 상태·비밀 모두 JSON 문자열 안쪽으로 이스케이프한다 — 방문자가 키를 끼워 넣지 못한다. 이스케이프한 비밀이 원문과 다르면
  파생값으로 `register_revealed`.
- **틀은 한 번에 치환**한다(정규식 한 번 훑기) — 방문자 글에 `{{secret.…}}`을 넣어도 다시 해석되지 않는다.
- **리다이렉트와 비밀(#32 함정)**: 보안 계층은 다른 호스트로 갈 때 `Authorization`·`Proxy-Authorization`·`Cookie`만 뗀다. HTTP 도구는 헤더·본문에
  비밀 참조가 하나라도 있으면 **다른 호스트로의 리다이렉트를 따르지 않는다**(`SafeHttpClient.request(cross_host_redirects=False)` →
  `cross_host_redirect`, 허용 목록 안의 호스트여도). 헤더 떼기 대신 거부를 고른 까닭: 307·308은 본문을 그대로 싣고 가므로 본문의 비밀까지 막으려면
  떼는 것으로 모자라고, 비밀 헤더 이름 규칙(이름 패턴)에 기대면 `X-Custom`처럼 이름이 안 맞는 헤더가 샌다. 비밀이 없는 요청은 허용 목록 안에서
  홉마다 다시 검사하며 따르고, 같은 호스트 리다이렉트는 비밀이 있어도 따른다.
- **실패 갈래**: 노드의 갈래는 `next`(2xx)·`error`(선택). 차단·시간 초과·크기·HTTP 4xx/5xx·JSON 아님(`save`가 있을 때)·실행 때 없는 비밀·예상 못 한
  예외는 턴을 깨지 않고 `error`로 간다(선이 없으면 턴 끝). 판단 기록 `record.error`에 이유 코드(safe_http 코드 + `http_error`·`invalid_json`·
  `unknown_secret`·`internal_error`), 문구는 호스트까지만.
- **가림**: 헤더·본문은 기록하지 않는다. `record`의 URL·저장 값·문구와 상태 `fields`에 쓰는 응답 값은 이 테넌트 비밀(원문·파생값·조각)로 가린다
  — 응답이 비밀을 되돌려 보내도(에코 API) 상태·체크포인트·판단 기록·시험 대화 trace에 남지 않는다.
- **시험 한 턴도 실제로 부른다**(갈래를 운영과 같게 — 사람 넘김처럼 흉내 내면 응답 경로를 시험할 수 없다). 체험 턴 규칙(ADR-0026)은 그대로.

## 보충 (#131): 가짜 API — 예약 호스트를 프로세스 안에서 처리

결정: 대장(조율자) 결정, 사용자 사후 보고 예정(되돌리기 쉬운 내부 구현이라 진행).

- 예제 흐름·`/try`의 HTTP 도구가 부를 「가짜 API」(주문 조회·레벨 테스트 예약·문의 접수 흉내)는 **예약 호스트** `demo-api.flow.sandcorp.co.kr`(상수
  `apps/flows/demo_api.HOST`, 실제 DNS에 없다)로 두고, HTTP 도구가 이 호스트를 **네트워크 없이 같은 프로세스의 결정적 핸들러로** 처리한다.
  운영 DNS·서버·네트워크 설정이 필요 없고, 외부 서비스가 내려가도 예제가 돈다.
- **전송 결정 지점은 하나**(`http_tool._send`): `urlsplit(url)`의 `scheme == "https"`이고 원문 authority(`netloc`)가 예약 호스트와 **글자 그대로 같을**
  때만 프로세스 안. 대문자·끝점 `.`·명시 포트(`:443` 포함)·하위 도메인·접미(`…co.kr.evil.com`)·IDN(키릴 문자 등)·`user@` 변형은 모두 지금처럼
  safe_http로 간다 — 비슷한 이름은 정규화하면 같은 호스트처럼 보여도 프로세스 안으로 보내지 않는다(닫힌 쪽: 헷갈리면 네트워크 경로의 검사를
  다 받는다). 허용 목록에 그 변형을 넣어 둔 테넌트에서도 safe_http가 실제로 해석하려 든다.
- 예약 호스트는 모든 테넌트의 허용 목록에 **암묵 포함**된다(허용 도메인 표에 저장하지 않는다). 편집기 경고(`admin/src/lib/httpToolWarn.ts`
  `isDemoApiUrl`)는 같은 정확 일치 규칙으로 경고 대신 「가짜 API」 안내를 보인다.
- **규칙이 갈라지지 않게**: 가짜 API는 `safe_http.SafeResponse`를 돌려주고 실패는 같은 `SafeHttpError` 코드다 — 상태 코드 → `http_error`,
  `save`·`invalid_json`, 가림, 판단 기록 모양이 실제 API와 같다. URL 단계 검사는 `safe_http.check_url`(예약 호스트 하나만 허용하는 정책)을 같이 쓰고,
  크기 한도는 같은 `Limits.max_body_bytes`. **지연 흉내는 실제로 자지 않는다** — 흉내 지연(30초)이 `Limits.total_timeout`을 넘으면 `timeout`.
  리다이렉트는 내지 않는다.
- **비밀**: 가짜 API는 요청 헤더를 읽지 않고 본문에서도 정해진 필드만 읽어 검증한 값(날짜·레벨)만 되돌린다 — 번호는 입력의 SHA-256 앞 4~6자.
  비밀을 실어도 응답·판단 기록에 원문이 없다(기록 쪽 가림은 그대로 한 번 더).
- **무상태·결정적**: 저장하지 않는다. 같은 입력이면 같은 번호. 엔드포인트·실패 흉내 규칙은 `docs/flow-json.md` 「가짜 API」.
- 시험: `tests/test_flow_demo_api.py` — 네트워크 대역(`safe_http.NETWORK`의 FakeDns·route·로컬 서버)에 조회 0·연결 0을 박고, 호스트 변형 표를 safe_http
  경로로 확인한다.
