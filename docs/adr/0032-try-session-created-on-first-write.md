# ADR-0032: 체험 세션은 첫 쓰기 때 만든다 — 방문 즉시 편집기

## Status
Accepted (2026-10-26, 사용자 결정 「방문 즉시 편집기」·설계 승인 Q1~Q7 — #194, 구현 #195~#199, 문서 #200)

## Context
전에는 `/try`(짧은 주소 → `/admin-ui/try`)가 템플릿 카드를 먼저 보여 주고, 「고쳐 보기」(임베드는 「고쳐 보기 시작」)를 눌러야
`POST /api/try/sessions/`가 체험 테넌트·예제 사본·`sf_try` 쿠키를 만들었다(ADR-0030, `try_api.try_start`). 이 한 번의 클릭이
IP 하루 3세션(`try_ip_days`)을 쓰는 지점이었고, ADR-0031은 임베드에서도 「방문만으로 세션을 만들지 않는다」를 지키려고 이 버튼을 남겼다.

사용자는 방문자가 버튼 없이 곧바로 편집기를 보길 원한다. 그런데 방문 때 세션을 만들면 봇·새로고침·「구경만 하는」 방문이
IP 한도와 숨은 테넌트(설정·키·흐름 행)를 쓴다. 다행히 세션 없이 읽는 길은 이미 있었다.

- `GET /api/try/templates/{id}/`가 세션 없이 예제 그래프를 준다(IP 한도 안 씀).
- `GET /api/try/node-schema/`도 세션 없이 노드 설정 폼의 틀을 준다.
- 편집기(`FlowEditorPage`)는 모든 편집을 패치 연산으로 하나의 직렬 큐(`commit`)에 넣어 저장하고, 마운트 때 스스로 쓰지 않는다.
  시험 대화는 보내기 전에 그 큐가 비기를 기다린다(`useTestSession(beforeSend)`).

즉 「읽기」는 세션이 필요 없고, 세션이 필요한 것은 **쓰기**(초안 저장·시험 대화·「이 흐름으로 가입」)뿐이다.

## Decision
**세션은 첫 쓰기 때 만든다. 클라이언트가 편집을 지역 그래프로 들고 있다가 첫 쓰기에 「그래프를 들고」 세션을 만든다(①b).**

1. **진입 = 편집기.** `/try?template=<짧은 이름|id>`(임베드 포함)는 카드 대신 그 템플릿의 편집기를 곧바로 그린다.
   그래프는 `GET /templates/{id}/`, 폼 틀은 `GET /node-schema/`, 새로고침 판단은 `GET /session/`으로 읽는다 — 서버에 아무것도 만들지 않는다.
   모르는 템플릿이면 카드 고르기로 돌아가 「그 템플릿을 찾지 못했어요」를 보인다.
   `template` 없는 `/try`는 템플릿 고르기 그대로이되(Q1), 카드의 「고쳐 보기」는 `/try?template=`으로 **이동만** 한다(POST 없음).
2. **첫 쓰기 = 세션 생성.** 설정 변경·연결·노드 추가/삭제로 이루어진 초안 저장, 시험 대화, 「이 흐름으로 가입」 중 먼저 오는 것이
   `POST /api/try/sessions/ {template, graph?}`를 부른다(`lazyTryBackend.ensureSession`). 서버는 한 트랜잭션에서 IP 한도(`admit_ip`)를 세고
   체험 테넌트·사본을 만든 뒤, `graph`가 오면 그 그래프를 초안으로 저장해(`services.save_draft`, PUT draft와 같은 검증, 별도 크기 한도 없이 같은 요청 본문 한도)
   응답 `draft: {graph, errors, valid}`로 검증 결과를 함께 돌려준다. `graph`가 없으면 템플릿 그대로이고 `draft`는 null이다(옛 번들 호환).
   쿠키·Origin 검사·만료(24h)·세션당 20턴은 그대로다.
   - **저장은 같은 트랜잭션이다.** IP 한도·모르는 템플릿·나쁜 Origin·저장 중 예외 어느 쪽이든 테넌트와 `try_ip_days`가 늘지 않는다(`graph`가 있어도).
   - **그래프가 나빠도 세션을 만든다(판단).** PUT draft가 「틀려도 저장하고 검증 결과를 돌려준다」와 같고, 만들지 않으면 사용자가 고치던 내용이 날아간다. 오류는 `draft.errors/valid`로 보인다.
3. **노드 위치 이동만으로는 첫 쓰기가 아니다(Q2).** 위치(`upsert_node {id, position}`만 있는 연산)는 세션을 만들지 않고 지역 그래프에만 담긴다.
   다음 진짜 쓰기·시험 대화·가입 때 함께 `graph`에 실려 들어간다.
4. **지역 그래프를 큐 순서대로 들고 있는다.** 세션이 없는 동안 `patchDraft`는 지역 그래프(템플릿 + 지금까지의 연산)를 갱신하고, 첫 쓰기가 그 전체를 `POST`에 싣는다.
   생성 중에 더 들어온 연산만 생성 직후 `PATCH /api/try/flows/{id}/draft/`로 따라가고, 그 뒤로는 기존 PATCH다. 한 탭 안에서 생성 POST는 한 번만 나간다(single-flight, 거절되면 약속을 비워 다음 쓰기가 다시 시도).
   - 초안(T1)의 ①a(「생성 `POST {template}` 뒤 대기 연산을 PATCH로 재생」)는 T1에서 임시로 썼고 T2(#196)가 ①b로 바꿨다. 지금 구현은 ①b뿐이다.
5. **세션 생성이 거절되면 편집은 화면에 남는다.** `try_ip_limit`(429)·`try_bad_origin`·네트워크 오류일 때 편집기는 서버 초안으로 「되돌리지」 않고 지역 그래프를 유지하며
   「저장하지 못했습니다: 오늘 이 네트워크에서…」를 보인다(저장·시험 대화는 안 됨). 시험 대화가 거절되면 보낸 말풍선과 사유가 남고 입력창에 쓴 글이 돌아온다.
   다음 쓰기는 연산 재생 없이 지금까지의 지역 그래프로 다시 생성을 시도한다.
6. **새로고침(#197).** 세션이 있으면 서버가 원본이다: `GET /session/`의 `template`이 지금 템플릿과 같으면 그 사본(`GET /flows/{flow_id}/`)을 연다(주소는 그대로).
   세션 생성 전(또는 거절된 동안)의 지역 그래프는 탭의 `sessionStorage['sandcorp-flow:try-draft:<template>']`에 두어 새로고침을 넘긴다(위치 이동 포함). 세션이 생기면 지운다.
   저장소 접근이 던지면 메모리만 쓴다. 보관본과 세션이 둘 다 있으면 보관본으로 열고, 다음 첫 쓰기가 사본을 덮는다.
   다른 템플릿의 세션이 진행 중이면 편집기 위에 「여기서 고치면 새 체험으로 바뀝니다」를 보이고 첫 쓰기 전에는 POST가 없다.
7. **두 탭 동시 첫 쓰기(Q6).** 서버에 멱등 키가 없으므로 생성 직전 `GET /session/`을 1회 확인한다. 같은 템플릿의 세션이 이미 있으면 POST 없이 그 세션을 쓰고
   `PUT /flows/{id}/draft/`로 지역 그래프를 덮는다. **지역 편집이 이긴다** — 사용자가 방금 한 것이고, 다른 탭의 사본은 같은 템플릿에서 시작한 것이라 「내가 보던 화면이 저장된다」와 일치하며 IP 한도·사본 중복도 막는다.
   확인과 POST 사이의 짧은 틈은 남는다(그때는 나중 쿠키가 이긴다).
8. **편집 중 만료(Q5).** 새 편집기는 24h 만료(401 `try_no_session`/404)에도 `/try?expired=1`로 튕기지 않는다. 「체험 시간이 지나 세션이 끝났어요…」 안내를 보이고
   **지역 모드**(편집 유지)로 돌아가 다음 쓰기에 새 세션을 만든다(IP 1). 옛 `/try/flow/:id`는 지금처럼 `/try?expired=1`로 보낸다.
9. **「이 흐름으로 가입」은 세션이 없으면 세션 먼저(Q4).** 세션이 없으면 링크를 중간 페이지 `/admin-ui/try/signup?template=…`(`TrySignupPage`)로 건다 —
   일반 화면은 `rel="nofollow"`, 임베드는 `target="_blank" rel="noopener nofollow"`(새 탭을 동기적으로 열어야 하므로 팝업 차단을 피한다).
   이 페이지는 `GET /session/`으로 확인해 세션이 없을 때만 `POST /sessions/` 1회 뒤 `claimLoginUrl()`로 `location.replace`한다. 거절이면 사유와 「체험으로 돌아가기」.
   - 같은 탭에 보관된 지역 그래프(`sessionStorage`)가 있으면 `graph`로 싣는다. **새 탭은 iframe과 sessionStorage가 달라 보통 없으므로 템플릿 그대로 만든다.** iframe 안의 미저장 위치 이동은 가입 사본에 실리지 않는다
     (첫 진짜 쓰기를 했다면 세션이 이미 있어 이 경로를 타지 않는다). 일반 화면은 같은 탭 SPA 이동이라 편집이 실린다.
   - 색인 제외: SPA가 이 페이지에서만 `<meta name="robots" content="noindex,nofollow">`를 넣고 떠나면 걷는다. nginx는 바꾸지 않았다.
   - 세션이 이미 있으면 지금처럼 곧바로 `claimLoginUrl()`이다.
10. **임베드의 「자동 세션 생성 금지」는 문장 그대로 지켜진다** — 진입은 세션을 만들지 않는다. 그래서 「고쳐 보기 시작」 버튼은 없앴다.
11. **읽기 전용 「흐름 보기」 화면은 없앤다(Q3).** `/try/view/:id`는 `/try?template=:id`로 replace 리다이렉트한다. 카드의 「흐름 보기」 버튼도 없다.
    공개 흐름 보기(`/flows/{slug}`, ADR 없음·#39)는 그대로다.
12. **임베드 첫 화면 배치(#199).** 격자가 한 줄로 쌓이는 폭(Tailwind `lg` 미만, 929px 등)에서 노드 목록 8칸이 캔버스를 밀어내던 것을,
    임베드일 때만 캔버스에 `order-first lg:order-none`을 주어 **캔버스를 먼저** 보이게 했다(노드 목록은 아래). 일반 화면 배치는 그대로다.
    이 폭에서 캔버스는 위쪽 약 100~520px에 보이고 내용 높이는 약 932px로 고정이며 부모에게는 높이 메시지로 전달된다. portfolio iframe의 초기 높이 권장값은 480px에서 **640px**로 올린다(`docs/deployment.md`).
13. **호환.** `/try/flow/:id`(지금 열린 탭·북마크)는 기존 `tryBackend`로 계속 연다. `POST /sessions/`의 `graph`는 선택 칸이라 캐시된 옛 번들(본문 `{template}`만)도 그대로 돈다.
    짧은 주소 301·`TRY_EMBED_ORIGINS`·CSP·portfolio iframe `src`(`/try?embed=1&template=home`)는 바꾸지 않는다.

## Alternatives
- **① a. 클라이언트 메모리 + 첫 쓰기에 `POST {template}` 후 대기 중인 연산을 PATCH로 다시 보낸다(백엔드 변경 없음).** T1(#195)에서 첫 tracer bullet로 쓰고 T2(#196)에서 ①b로 바꿨다.
  세션 생성이 한 번 거절된 뒤 쌓인 편집을 연산 묶음으로 재생해야 하고(`delete_node`·`connect` 재생은 멱등이 아니라 묶음 전체가 거절될 수 있다), 요청이 둘이다. ①b(그래프를 들고 생성)를 채택한다.
- **② 진입 때 익명 「가벼운 세션」(쿠키 + `TrySession` 행)만 만들고 체험 테넌트는 첫 쓰기에 만든다.** 기각.
  방문마다 쿠키·DB 행이 생겨(봇·크롤러 포함) ADR-0031이 막으려던 「방문이 상태를 만든다」가 돌아온다. `TrySession.tenant`가 비어 있을 수 있게 되어 `resolve`·정리·`claim`·모든 `/flows/` 어댑터에 「테넌트 없으면」 갈래가 생긴다.
- **③ 현행 유지(「고쳐 보기」 클릭 = 세션).** 기각. 사용자 결정(방문 즉시 편집기)에 어긋난다. 한도 면에서는 ①과 같은 수준인데(둘 다 「의도 있는 행동」 한 번에 1세션) 첫 화면에 카드와 버튼이 하나 더 있다.
- **④ 진입 때 세션을 만들되 IP 한도는 첫 쓰기에 센다.** 기각. 한도가 체험 테넌트 생성 수를 막지 못해 봇이 테넌트를 무한히 만든다.
- **노드 위치 이동도 첫 쓰기로 친다.** 기각(Q2). 초안은 「위치도 첫 쓰기」를 권장했으나, 포트폴리오 홈 iframe에서 장난삼아 노드를 한 번 끌어도 세션·IP 1이 생기는 것을 피한다.
- **서버 멱등 키로 두 탭 동시 생성을 막는다.** 기각(Q6). 쿠키가 없는 요청 둘을 묶을 키가 없다. 생성 직전 `GET /session/` 확인으로 충분하다.

## Consequences
- 서버 상태는 「의도 있는 첫 쓰기」에서만 생긴다. 구경만 하는 방문·봇·새로고침·노드 위치 이동은 IP 한도·테넌트·비용을 쓰지 않는다.
- IP 하루 3세션은 **첫 쓰기 때** 센다(시점만 바뀌고 장치·값은 그대로). 거절되어도 편집은 화면(과 `sessionStorage`)에 남는다.
- `try_expires_at`(24h)은 진입이 아니라 첫 쓰기(세션 생성)에서 잰다. 정리 작업(`prune_try_tenants`)·기준 칼럼·cron은 바뀌지 않는다. 구경만 한 방문은 정리할 것 자체가 없다.
- 지역 그래프(`sessionStorage`)는 서버 상태가 아니라 정리 대상이 아니다 — 탭을 닫으면 사라진다. 의도된 것이다(「저장 전 편집은 화면에만」).
- 세션 생성 전에는 서버 검증 결과가 없다(템플릿은 유효하다). 첫 쓰기 응답부터 검증 오류가 보인다.
- 「남은 대화 N턴」은 세션이 생긴 뒤부터 보인다(그 전에는 「첫 저장 때 체험이 시작돼요」 한 줄).
- 두 탭이 거의 동시에 첫 쓰기를 하면, 확인 틈에 걸린 경우 세션이 둘 생기고 나중 쿠키가 이긴다. 먼저 만든 탭의 다음 쓰기는 404/401이므로 위 8의 만료 안내와 지역 모드로 돌아간다.
- 이름 칸은 블러에 커밋한다(설계). 세션 생성 직후 이어 친 글자가 다음 블러까지 커밋되지 않는 것은 이 설계 때문이며, 생성이 서버 사본으로 지역 상태를 바꿔 끼우는 일은 없다(회귀 시험이 있다). 이름 칸 입력 중 자동 커밋은 후속 후보다.
- 테넌트 편집기(`tenantBackend`)·공개 흐름 보기·`/api/tenant/flows`는 바뀌지 않는다. 바뀐 곳은 체험 편집기 백엔드(`lazyTryBackend`)·`/try` 화면·`/try/signup` 중간 페이지·`POST /api/try/sessions/` 하나다(orval 재생성함).
