# ADR-0027: 흐름은 바뀌지 않는 JSON 버전, 실행기가 대화마다 StateGraph로 해석

## Status
Accepted (2026-10-24, 사용자 결정)

## Context
지금 챗은 코드에 박힌 `build_graph`(`apps/agent/graph.py`) 하나로 돈다: 지식 검색 → LLM(structured) → 필요 시
`create_escalation`. Sandcorp Flow에서는 테넌트가 편집기에서 노드와 선을 그리고, 초안을 시험한 뒤 배포한다.
이미 진행 중인 대화가 편집 때문에 깨지면 안 되고, 배포한 것은 한 번에 되돌릴 수 있어야 한다.

## Decision
- **흐름 버전 = 바뀌지 않는 JSON.** 흐름(Flow)은 버전(FlowVersion)들을 가진다. 버전은 노드·선·노드 설정을 담은 JSON이며
  저장한 뒤로 고치지 않는다. 편집은 **초안**(하나, 고칠 수 있음)에서만 하고, 「배포」가 초안을 새 버전으로 굳힌다.
- **배포 절차**: 초안 → 시험(시험 대화) → 배포. 흐름마다 **배포 중 버전**이 하나 있고, 되돌리기는 이전 버전을 배포 중으로
  바꾸는 한 동작이다. 테넌트 설정 「배포에 관리자 승인 필요」를 켰을 때만 「배포 요청」 단계가 생긴다(승인 권한이 배포한다).
- **대화는 버전에 고정된다.** ChatSession은 시작할 때의 버전을 기록하고 끝까지 그 버전으로 돈다(배포가 진행 중 대화를 바꾸지 않는다).
- **실행기는 해석기다.** 대화 턴마다 실행기가 버전 JSON을 LangGraph `StateGraph`로 짓는다(코드 생성 없음). 버전 해시로
  지은 그래프를 캐시할 수 있다. **노드 종류마다 파이썬 핸들러 하나**를 레지스트리에 등록한다. JSON 검증(알 수 없는 종류,
  끊긴 선, 시작 노드 하나, 조건 분기의 빈 갈래)은 저장·배포 때 하고 실행 때 다시 믿지 않는다.
- **체크포인트·HITL·SSE는 그대로 재사용**: `thread_id = session_id`, AsyncPostgresSaver, Redis pub/sub SSE, Escalation 모델.
  「사람 넘김」 노드가 기존 `create_escalation` 경로를 탄다.
- **첫판 노드 일곱 종 + HTTP**: 시작, AI 답변, 조건, 사람 넘김, 지식 검색(GraphRAG), AI 분류·추출(확신도를 함께 냄),
  가드레일(금지어·개인정보·가격 약속을 막거나 다시 씀), HTTP 도구(ADR-0029).
- **판단 기록(Decision Trace)**: 턴마다 노드별 입력·출력·분기 이유·토큰·비용·걸린 시간을 남긴다. 편집기 시험 대화와
  운영 대화 모두 같은 형식이다. 비밀 값은 기록 전에 가린다.

## Considered Options
- **흐름을 파이썬 코드로 생성해 배포**: 기각. 코드 실행 표면이 생기고 버전 고정·되돌리기가 배포 파이프라인에 묶인다.
- **LangGraph 없이 자체 상태 기계**: 기각. 체크포인트·interrupt(HITL)·스트리밍을 다시 만들어야 한다.
- **버전을 고칠 수 있게(행 갱신)**: 기각. 진행 중 대화와 판단 기록이 무엇으로 돌았는지 재현할 수 없다.

## Consequences
- 기존 `build_graph`는 「기본 흐름」(시작 → 지식 검색 → AI 답변 → 사람 넘김)의 JSON으로 옮겨지고, 가입한 테넌트는 그 흐름으로 시작한다.
- 노드 핸들러는 공통 입출력 계약(상태 읽기·쓰기 키, 판단 기록 항목)을 따른다. 새 노드는 핸들러와 JSON 스키마만 더한다.
- 비용 계산에 모델별 단가 표가 필요하다(판단 기록의 비용, 체험 한도, `/try` 하루 상한이 함께 쓴다).

## 보충: 검증 규칙과 순환(2026-10-24, #22)
- **스키마·검증 모듈**: `backend/apps/flows/schema.py`. `validate_flow(data) -> list[FlowError]`(빈 목록이면 유효),
  `parse_flow(data) -> FlowGraph`(무효면 `FlowValidationError`). 오류는 `{node_id, code, message}` — 편집기가 노드에 표시한다.
  형식은 `docs/flow-json.md`.
- **검증 시점**: Flow Version을 만들 때(`FlowVersion.save`) 검증하고 무효면 만들지 않는다. 초안은 작업본이라 무효여도 저장된다.
- **순환은 허용하되, 턴 경계를 지나야 한다.** 되묻기(예: 「요구사항 되묻기」 → 「의도 분류」로 돌아감)는 같은 노드로
  돌아가는 길이 필요하다. 그래서 순환을 막지 않고, **순환마다 방문자 답을 기다리는 노드**(지금은 `await_reply: true`인
  AI 답변)를 하나 이상 지나야 한다고 정한다. 실행기는 그런 노드에서 답을 보낸 뒤 턴을 끝내고, 다음 턴은 그 노드의 나가는
  선에서 이어 간다. 경계 없는 순환은 한 턴 안에서 끝없이 돌므로 저장 때 `cycle_without_turn_boundary`로 거부한다.
- **무한 루프 상한**: 위 규칙으로 한 턴 안의 무한 루프는 정적으로 막히지만, 실행기는 안전장치로 한 턴에 노드
  `MAX_STEPS_PER_TURN`(50)개까지만 실행한다(넘으면 턴을 실패로 끝내고 판단 기록에 남긴다). 턴을 건너는 되묻기는
  매번 방문자 메시지가 있어야 돌므로 계산 폭주가 아니다. 되묻기 횟수 상한은 노드 티켓에서 정한다.
- **갈래**: 조건 노드는 `branches[].name`과 `else` 갈래를 가지며 **모든 갈래에 선이 있어야 한다**(빈 갈래 금지).
  다른 노드는 `next` 갈래 하나(선이 없으면 거기서 턴이 끝난다), 사람 넘김은 나가는 선이 없다. 한 갈래에서 선은 하나,
  시작 노드로 들어오는 선은 없다.
- **비밀**: HTTP 도구의 인증 계열 헤더(Authorization·Cookie·*token*·*secret*·*api-key*·*password*) 값은
  `{{secret.이름}}` 참조(앞에 스킴 한 단어 허용, 예: `Bearer {{secret.key}}`)만 받는다. 원문을 넣으면 `invalid_config`.
- **공개 흐름**: 테넌트당 하나의 Flow를 `is_public`으로 정한다(부분 유일 제약). 새 ChatSession은 만들어질 때
  그 Flow의 배포 중 버전을 `flow_version`에 고정한다(없으면 비워 둔다 — 기존 세션도 비어 있다).

## 보충: 운영 챗 전환(2026-10-24, #72)
- 운영 챗(taskiq worker-chat 한 턴)은 실행기로 돈다. `build_graph`는 지웠다. 진입은 `apps/flows/chat_turn.run_chat_turn_async`.
- **고정 버전이 없는 세션**(이 칸이 생기기 전 세션)은 첫 턴에 그 테넌트 공개 흐름의 배포 중 버전에 고정해 이어 간다. 공개 흐름이 없는 테넌트는 고정하지 않고 기본 흐름(`DEFAULT_FLOW`)으로 돈다.
- **배포 순간 진행 중이던 대화**: 체크포인트 자리(thread_id=세션)는 그대로다. 옛 그래프 체크포인트에는 재개 지점이 없으므로 새 턴은 시작 노드부터 돌고, 대화 기록(`messages`)은 그 위에 이어 쌓인다. 옛 그래프가 턴 중간에 멈춘 체크포인트도 새 입력으로 덮어 시작한다(시험 `test_chat_executor_cutover`).

## 보충: 가드레일과 스트리밍(2026-10-24, #26)
- **가드레일 뒤의 AI 답변은 흘리지 않고 모아 둔다.** AI 답변이 토큰 단위로 위젯에 이미 흘러간 뒤 가드레일이 막으면 늦다. 그래서 바로 뒤에 출력 가드레일이 붙은 AI 답변은 스트림 발행을 건너뛰고(`NodeContext.hold_stream`), 가드레일이 통과시킨 글을 한 번에 내보낸다(첫 토큰이 늦어지는 대가). 넘김 턴(#25)처럼 가드레일이 붙은 흐름에서도 넘김이 결정된 턴엔 모델 답이 나가지 않는다. 답을 보낸 뒤 턴이 끝나는 `await_reply` AI 답변 바로 뒤에는 출력 가드레일을 못 붙인다(저장 시 `guardrail_after_await_reply`).
- 판정을 못 하거나(가격 약속 LLM 실패) 다시 쓰기에 실패하면 원문을 내보내지 않고 정해 둔 문구로 막는다(닫힌 쪽으로).
